# Вход по паролю и через Google

Обновлено 23 сентября 2026. Код приложения поддерживает регистрацию/вход с паролем, восстановление и Google OAuth. Исходные `.env.local` и история сохраняются.

## Обновление существующей базы

В Supabase → SQL Editor выполните весь [SUPABASE_AUTH_UPDATE.sql](../SUPABASE_AUTH_UPDATE.sql). Он обновляет только проверку недавнего входа перед удалением аккаунта, добавляя пароль и OAuth. Таблицы и история не удаляются. Для нового проекта [SUPABASE_SETUP.sql](../SUPABASE_SETUP.sql) уже содержит обе миграции.

## Адрес приложения

В **Authentication → URL Configuration**:

- **Site URL:** адрес, по которому вы действительно открываете приложение, например `http://127.0.0.1:3100`.
- **Redirect URLs:** добавьте `http://127.0.0.1:3100/auth/callback` и `http://127.0.0.1:3100/auth/callback?intent=recovery`.
- Если используете dev-сервер по `http://localhost:3000`, добавьте также `http://localhost:3000/auth/callback` и `http://localhost:3000/auth/callback?intent=recovery`. Site URL выбирайте соответствующий текущему окружению.
- Для публикации добавьте аналогичные адреса с вашим HTTPS-доменом и замените Site URL.

`localhost` и `127.0.0.1` — разные браузерные адреса: не начинайте вход на одном и не завершайте на другом. Google PKCE требует возврата в браузер, где начат вход.

## Пароль и письма

Включите **Email** в провайдерах Auth и разрешите регистрацию. Подтверждение почты можно оставить включённым. Рекомендуем минимальную длину пароля 8 символов в настройках Supabase; интерфейс использует такой же минимум для новых паролей.

Старые аккаунты, созданные через код/ссылку, могут ещё не иметь пароля. Нажмите **«Забыли пароль?»**, укажите прежнюю почту и задайте пароль через письмо. Новый аккаунт создавать не нужно, история останется у того же пользователя.

### Confirm signup

В **Authentication → Email Templates → Confirm signup** замените старое письмо с кодом на ссылку:

```html
<h2>Подтвердите почту для Luna Voice</h2>
<p><a href="{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&amp;type=signup">Подтвердить почту и войти</a></p>
<p>Если вы не создавали аккаунт, проигнорируйте письмо.</p>
```

### Reset password

В **Reset password**:

```html
<h2>Новый пароль для Luna Voice</h2>
<p><a href="{{ .SiteURL }}/auth/callback?token_hash={{ .TokenHash }}&amp;type=recovery">Задать новый пароль</a></p>
<p>Если вы не запрашивали смену пароля, проигнорируйте письмо.</p>
```

Эти шаблоны используют Site URL и позволяют открыть письмо в другом браузере. Также поддерживается стандартная ссылка `{{ .ConfirmationURL }}`: при PKCE её нужно открывать в браузере, где запрошено письмо. Повторно использованная или истёкшая ссылка покажет ошибку с возвратом ко входу. Уже присланные старые письма не меняются — запросите новое подтверждение или восстановление.

SMTP нужен для доставки внешним пользователям; встроенная отправка Supabase ограничена. Если письма уже приходят, смена способа входа не требует замены SMTP. [Документация писем](https://supabase.com/docs/guides/auth/auth-email-templates), [SMTP](https://supabase.com/docs/guides/auth/auth-smtp).

## Google

1. В **Google Cloud Console → Google Auth Platform** настройте приложение/экран согласия. Для режима Testing добавьте нужные почты в список Test users.
   В **Data Access** должны быть разрешены `openid`, `userinfo.email` и `userinfo.profile`.
2. Создайте **OAuth Client ID → Web application**.
3. В **Authorized JavaScript origins** добавьте используемый адрес приложения, например `http://127.0.0.1:3100`, а для публикации — HTTPS-домен.
4. В **Authorized redirect URIs** укажите callback Supabase, а не приложения. Для текущего проекта:

   ```text
   https://aurrowpcnqnpjidclbsj.supabase.co/auth/v1/callback
   ```

5. В **Supabase → Authentication → Sign In / Providers → Google** включите провайдера и вставьте **Client ID** и **Client Secret** из Google. Сохраните. Client Secret хранится только в Supabase; в `.env.local` и клиентский код он не нужен.
Публичная проверка 23 сентября: `/auth/v1/settings` возвращает `external.google: false` — в текущем проекте Google выключен. До включения кнопка показывает сообщение и остаётся на форме входа. Для включения нужны настройки владельца проекта в Google Cloud и Supabase; клиентский публичный ключ приложения не даёт права их менять.

6. Проверьте адреса возврата из раздела выше и нажмите «Продолжить с Google» в приложении.

### Быстрые ссылки для текущего проекта

- [Создать OAuth-клиент Google](https://console.cloud.google.com/auth/clients): тип **Web application**, имя **Luna Voice**. Для текущего локального запуска origin — `http://127.0.0.1:3100`, redirect URI — `https://aurrowpcnqnpjidclbsj.supabase.co/auth/v1/callback`.
- [Провайдеры Supabase](https://supabase.com/dashboard/project/aurrowpcnqnpjidclbsj/auth/providers): откройте **Google**, включите провайдера, вставьте Client ID / Client Secret, сохраните.
- [URL Configuration Supabase](https://supabase.com/dashboard/project/aurrowpcnqnpjidclbsj/auth/url-configuration): Site URL — `http://127.0.0.1:3100`, разрешённый адрес возврата для Google — `http://127.0.0.1:3100/auth/callback`.

После сохранения настроек сервер приложения перезапускать не нужно. Откройте приложение по указанному адресу и выполните вход через Google. Успешное включение провайдера ещё не подтверждает правильность Client Secret и redirect URI: окончательная проверка — реальное возвращение из Google в аккаунт Luna Voice и сохранение входа после перезагрузки.

[Официальная инструкция Supabase для Google](https://supabase.com/docs/guides/auth/social-login/auth-google).

## Как работает возврат

`/auth/callback` обрабатывает PKCE `code`, email `token_hash` и старые ссылки с токенами в URL-фрагменте. Корневая страница тоже понимает старые ссылки. Одноразовый обмен выполняется один раз, в том числе в React Strict Mode. Параметры с токенами убираются из адресной строки; внешние `next`/redirect-адреса не используются. Возврат ведёт только в аккаунт Luna Voice.

После recovery-ссылки показывается отдельная форма нового пароля. Её состояние сохраняется при перезагрузке в текущей вкладке и очищается после успешного обновления. Обновление пароля вызывает Supabase Auth; само приложение не хранит пароли.

Удаление аккаунта требует ввода «УДАЛИТЬ» и недавней аутентификации. Для email проверяется текущий пароль. Для Google нужен OAuth-вход в последние 15 минут; кнопка повторного входа возвращает в приложение, после чего удаление подтверждается вручную. Возврат от Google сам по себе никогда не удаляет аккаунт.

## Приёмка

Проверьте на настоящем проекте: регистрация → письмо → подтверждение → выход → пароль; старый аккаунт → восстановление → новый пароль; Google → согласие → возвращение; отмена Google и просроченное письмо; удаление тестового аккаунта. Автотесты используют имитацию API и проверяют код переходов, но не доступность реальной почты и настройки Google Console.
